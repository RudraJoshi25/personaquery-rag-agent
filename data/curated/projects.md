## PersonaQuery — grounded RAG over personal documents

**What it is:** A retrieval-augmented generation assistant that answers
questions about Rudra strictly from his own documents — resume, research
paper, patent, transcripts and project docs — with inline citations and
prompt-injection guardrails. It powers the "Ask AI" assistant embedded in the
portfolio site.

**Repository layout:** FastAPI backend (`app/backend`), Next.js frontend
(`app/frontend-next`), deployed backend on Render and frontend on Vercel.

**Retrieval pipeline:**
- Dense embeddings: `all-MiniLM-L6-v2`, 384-dimensional, cosine similarity
- Sparse keyword search: BM25 (Okapi, via `rank-bm25`)
- Fusion: Reciprocal Rank Fusion, k=60 — chosen because it needs no score
  calibration between BM25 and cosine, which are not on comparable scales
- Section-aware chunking with per-document-type profiles: resumes and
  transcripts chunk finely at 90–110 words with atomic bullet grouping,
  papers use 220-word windows
- Vector store: NumPy matrix plus JSONL chunks; Chroma available as an
  alternative backend. No external vector database.

**Generation:** Claude (Anthropic Messages API) at temperature 0.2, with
`claude-sonnet-5` for answers and `claude-haiku-4-5` for internal query
expansion. An earlier version ran a four-provider failover chain (Groq,
Cerebras, NVIDIA NIM) built around free-tier token limits; that was removed
once generation moved to prepaid Anthropic credits, since the chain existed
only to work around per-minute quota caps.
Answers must cite their sources with inline `[[cite:N]]` markers, and a
cite-only-if-used rule strips sources the model did not actually rely on.

**Engineering practices:** prompt-injection guardrails, per-IP rate limiting,
a response cache, retry-with-backoff resilience around the LLM call,
structured JSON logging with trace IDs, latency instrumentation, a golden-set
evaluation harness, and a CI pipeline that runs tests and the eval gate on
every push.

**Evaluation:** a 20-item golden set measuring retrieval hit-rate and
recall@k, answer keyword match, and citation compliance. Most recent run:
retrieval hit-rate 1.0, mean recall@k 1.0, answer pass rate 0.95, citation
pass rate 1.0, source precision@k 0.65.

## HealthEcho — symptom analysis chatbot

**What it is:** A web app where users describe symptoms in plain text and
receive brief health advice generated by a hosted LLM.

**Architecture:** Next.js 15 frontend (React, TypeScript, Tailwind CSS) posting
to an Express.js backend, which calls Together AI's
`Mixtral-8x7B-Instruct-v0.1` and returns the advice, rendered with a
typewriter animation.

**Endpoints:**
- `GET /api/health/check` — health check
- `POST /api/analyze/symptoms` — accepts `{ symptoms }`, returns
  `{ status, advice }`

**Deployment:** local development only at time of writing — no Docker, no
CI/CD.

## JobPilot / job-agent — multi-agent job application pipeline

**What it is:** A five-layer multi-agent system that automates the job
application pipeline, from sourcing listings to tailoring documents and
applying.

**Architecture (from ARCHITECTURE.md):**
- **Layer 1 — agents:** source, normalizer, match, resume, cover letter, QA,
  apply
- **Layer 2 — guardrails engine** (`core/guardrails.py`): wraps every agent
  call. Input checks are schema validation, PII detection (passwords/tokens
  in prompts), token-budget warnings above 8000 tokens, and a rate limiter
  enforcing 5 seconds between API calls. Output checks are a hallucination
  detector for fabricated companies/dates/skills, output schema validation,
  a quality floor on minimum word count, and a cost tracker logging tokens
  and running spend.
- **Layer 3 — skill hooks** (`core/skill_hooks.py`)
- **Layer 4 — dynamic orchestration** (`agents/master_agent.py`): priority
  queue, routing, retry logic, skill integration
- **Layer 5 — strategic agent** (`agents/strategic_agent.py`): weekly
  performance analysis and recommendations

**Model routing:** writing agents (resume tailoring in LaTeX, cover letter
generation via a critic-actor loop, strategic role targeting) run on Claude
Opus; routing and utility agents (orchestration, JD scoring) run on Claude
Haiku. Model selection is deliberate and rate-limit aware.

**Stack:** Python, Anthropic SDK, Playwright for browser automation, Pydantic
for schemas, Tenacity for retries, python-docx, PyYAML.

**Repository:** https://github.com/RudraJoshi25/JobPilot

## Deep Reinforcement Learning — algorithm benchmarking study

**What it is:** A comparative analysis of deep RL algorithms in continuous
action spaces — DDPG, TD3, SAC and PPO — structured as a set of research
questions.

**Structure:** six research-question directories (RQ-1 through RQ6) covering
basic algorithm performance, comparative analysis, advanced performance
metrics and extended results, plus per-algorithm analysis directories:
`DDPG_analysis`, `TD3_Analysis`, `SAC_Cont_Analysis`, `PPO_Cont_Analysis`.

**Focus:** reward convergence, training stability, and sample efficiency
across random seeds — the axes on which these algorithms actually differ in
practice, as opposed to headline final scores.

**Stack:** Python 3.7+, OpenAI Gym and MuJoCo environments. MIT licensed.

**Repository:**
https://github.com/RudraJoshi25/Deep-Reinforcement-Learning

## Cognitive-Chair — brain-sensing wheelchair

**What it is:** An AI-based brain-sensing wheelchair for paraplegic and
quadriplegic users, controlled through EEG and EOG signals (via a
brain-computer interface) instead of the joystick a conventional electric
wheelchair requires — aimed at users who cannot operate a joystick at all,
not just at reducing joystick precision requirements.

**How it works, at a high level:** electrodes pick up brainwave activity
(the paper works with the standard Gamma/Beta/Alpha/Theta/Delta EEG bands),
a processing pipeline extracts features and decodes intended movement from
that signal, and the decoded command drives the wheelchair's motor
controller. The system architecture follows the general BCI pattern —
sense, decode, act — applied specifically to wheelchair navigation.

**Recognition:** Best Paper Award at the 4th International Conference on
Artificial Intelligence and Speech Technology (AIST-2022), organised by the
Centre of Excellence – Artificial Intelligence.

**Publication:** IEEE Xplore —
https://ieeexplore.ieee.org/document/10065338

**Co-authors:** Kshitij Joshi, Abhilasha Vyas, Smit Joshi and others, with
Rudra Joshi as a co-author. Carried out during the B.Tech at GSFC University.

**Related patent:** *Intelligent Face Recognition System using Deep Recurrent
Neural Network*, Indian patent application 202211058943 A, filed
15 October 2022 — a CNN+RNN based face recognition system, a separate piece
of work co-filed with the same research group.

## Personal portfolio site

**What it is:** Rudra's portfolio at which this assistant lives — a
React single-page site presenting his work, with PersonaQuery embedded as an
"Ask AI" assistant.

**Stack:** React 18 (Create React App), React-Bootstrap, GSAP with
ScrollTrigger for motion, and an Express + Nodemailer server backing the
contact form.

**Notable implementation details:** the desktop experience is a full-page
section deck rather than a scrolling document — wheel input advances between
Home, Skills, Projects and Contact, and within Projects it moves horizontally
through project panels before releasing to the next section. Below 900px it
degrades to native scrolling. The PersonaQuery drawer is integrated so that
citation chips in an answer navigate the page to the relevant section, and
project cards can pre-fill the assistant with a question about themselves.
